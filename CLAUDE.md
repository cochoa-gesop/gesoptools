# gesoptools

R package for internal use at GESOP: connection to the Integra database, survey
data export to SPSS/Excel, and SPSS dictionary processing.

Not on CRAN. Installed from GitHub:

```r
remotes::install_github("GESOP-org/gesoptools")
```

## MANDATE: bump the dev version on every pushed update

**Any change to this repo that gets pushed must also bump `Version:` in
`DESCRIPTION`.** No exceptions for "small" changes. Do it in the same commit as
the change, not a separate follow-up.

The scheme is a development version: `0.0.0.9000`, `0.0.0.9001`, `0.0.0.9002`, …
Increment the last component by one.

```
Version: 0.0.0.9001
```

### Why this is not optional

The package has no auto-update mechanism. Coworkers keep whatever commit they
installed until someone tells them to reinstall, and deployed shinyapps.io apps
pin an exact commit SHA in their manifest. The version string is the *only*
signal anyone has about what they are actually running — `packageVersion("gesoptools")`
is how a coworker checks whether they are current, and how you say "you need at
least 0.0.0.9004 for this fix."

If the version never moves, two people can get different export behaviour from
what looks to both of them like the same package. That is the failure this
mandate exists to prevent.

Skip the bump only for changes that cannot affect an installed copy: edits to
`README.md`, `CLAUDE.md`, or generated files under `docs/`.

## Layout

| Path | Notes |
|---|---|
| `R/integra_export.R` | All package code — single ~1400-line file |
| `man/*.Rd` | **Generated by roxygen2. Do not hand-edit.** |
| `NAMESPACE` | **Generated by roxygen2. Do not hand-edit.** |
| `vignettes/*.Rmd` | Source articles (quickstart, export, shiny, credentials) |
| `_pkgdown.yml` | pkgdown site config |
| `docs/` | **Generated by pkgdown.** Rebuild, don't hand-edit |

Exported functions: `db_config_from_env()`, `export_integra()`,
`load_integra_study()`, `apply_variables_dict()`.

Internal helpers are prefixed with a dot (`.build_unified_df()`,
`.expand_multi_response()`, `.build_spss_df()`, …) and are not exported. Keep that
convention — the dot prefix is the signal that a function is internal.

## After changing code

Roxygen comments live above each function in `R/integra_export.R`. If you touch a
roxygen block (`@param`, `@return`, `@export`, …), regenerate:

```r
roxygen2::roxygenise()   # or devtools::document()
```

Then commit the resulting `man/` and `NAMESPACE` changes alongside the code.

Adding or removing an exported function also means updating the `reference:`
section of `_pkgdown.yml` — pkgdown errors if an exported function is missing
from it.

To rebuild the documentation site:

```r
pkgdown::build_site()
```

R is not on `PATH` here; use the full path, e.g.
`"C:\Program Files\R\R-4.5.3\bin\Rscript.exe"`.

## Conventions

- Code comments and user-facing messages are in Spanish; keep that.
- Section banners (`# ----- ... -----`) group related helpers in
  `R/integra_export.R`. Put new helpers in the matching section.
- Dependencies are declared in `Imports:` in `DESCRIPTION` and called with
  `pkg::fun()`. Adding a new package means adding it to `Imports:` too.

## Deployment note

Apps on shinyapps.io rebuild this package from GitHub at deploy time, reading
`RemoteUsername`/`RemoteRepo`/`RemoteSha` from the *installed* copy in the
deploying machine's R library. A developer whose local copy was installed from
the old `cochoa-gesop` path will bake that into the manifest, so reinstall from
`GESOP-org` before deploying:

```r
remotes::install_github("GESOP-org/gesoptools", force = TRUE)
```

`force = TRUE` matters — the SHAs are identical after the org transfer, so
`remotes` otherwise skips the install and leaves the old path in place.
